CSV에서 URL을 조합해 탭을 옮겨 다니는 병목을 없애려고 Playwright 자동화와 Flask 컨트롤 패널을 직접 만들었습니다. 하지만 로그인 세션 안정성이 검수 신뢰도를 오히려 떨어뜨린다고 판단되자 수동 검수로 되돌렸습니다. 도구는 품질을 보장하기 위한 수단이라는 우선순위를 지킨 결정입니다. 히라가나도 모르는 상태로 시작한 업무였기에 5월부터 일본어를 직접 학습했고 지금은 콘텐츠의 문장 구조와 검수자 인사이트 문서를 스스로 읽으며 작업하고 있습니다.

IT 학습 플랫폼 및 콘텐츠 QA

78개 트랙과 약 7천 개 학습 task를 가진 IT 학습 플랫폼의 콘텐츠 QA를 총괄하고 있습니다. 방법론을 12종의 재사용 스킬로 체계화해 36개 트랙에 52건의 QA 커밋을 남겼습니다.

자동 검수를 다 통과한 트랙이 사실은 학습이 불가능한 구조였습니다

Linux 입문 트랙은 스키마와 정답 개수 같은 기계적 QA를 전부 통과했지만 직접 읽어보니 한 단원은 21개 task가 전부 읽기 자료이고 확인 퀴즈가 하나도 없었습니다. 어떤 자동 규칙에도 걸리지 않는 문제였습니다. 중복 실습 42건을 삭제하고 확인 없이 연속으로 읽어야 하는 구간의 길이를 기준으로 재진단해 신규 퀴즈 18건을 설계해 배치했습니다. 152개 task를 91개로 줄였다가 123개로 다시 채웠습니다. 단순 삭제가 아니라 무엇을 남기고 무엇을 새로 채울지 정하는 재설계였습니다.

트랙 하나의 오류를 저장소 전체 점검으로 확장했습니다

한 트랙에서 학습 경로 데이터가 실제 콘텐츠와 어긋난 것을 발견하고 이 트랙만의 문제인지 확인하기 위해 조사를 저장소 전체(580개 파일, 6,916개 task)로 넓혔습니다. 서로 다른 두 트랙이 같은 task 식별자를 쓰고 있어 플랫폼이 학습자 진행률을 저장하면 두 트랙의 기록이 섞일 수 있는 문제 등을 찾아 모두 바로잡았습니다. 이때 쓴 검증 지표 10개를 어떤 작업이든 전후로 반드시 돌려보는 체크리스트로 문서에 고정해 하나라도 어긋나면 그 작업이 문제를 만든 것으로 판정되게 했습니다.

검수 방법의 오탐을 찾아 바로잡았습니다

입문 트랙의 코딩 과제가 중급 트랙에서 처음 가르치는 문법을 미리 요구하는 결함을 발견했습니다. 트랙 하나씩 보는 기존 QA로는 원리적으로 잡을 수 없는 유형이라 과목의 모든 트랙을 학습 순서대로 이어 붙여 각 개념이 어디서 처음 가르쳐지고 어디서 쓰이는지 대조하는 검수 모델을 새로 만들었습니다. 이 검수의 첫 실행이 치명 등급 결함 20건을 보고했는데 콘텐츠 본문과 대조하니 실제 결함은 4건이었습니다. 오탐률 80%라는 사실을 숨기지 않고 결과 문서 맨 위에 정정 내용으로 밝힌 뒤 판정 기준을 고쳐 다시 검사했습니다.
